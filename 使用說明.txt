基金雷達｜GitHub Pages 部署修復（2026/11/24）

問題：2026/11/24 GitHub Actions #90、#91 已產生 github-pages Artifact，
但部署步驟回報 No artifacts named "github-pages" were found。
11 檔基金的更新程式已經推送到 GitHub，無需刪除重新安裝。

修正：
1. 將原本單一 Job 分成「build」及「deploy」兩個 Job；deploy 需等待 build 完成。
2. 上傳網站檔案後，增加等待時間，緩解 Artifact API 同步延遲。
3. 附加 favicon 檔案到發布內容，保留原本網址列圖示。
4. 保留每天三次自動更新及手動更新功能。
5. 避免基金資料寫回步驟因部署失敗而完全沒有執行。

上傳方式：
1. ZIP 解壓縮後，找到 .github/workflows/update-and-deploy.yml。
2. 到 https://github.com/c87038-droid/fund-radar
3. 點選 .github → workflows → update-and-deploy.yml。
4. 按右上角鉛筆編輯，將本檔內容全數取代原內容，點 Commit changes。
   若使用 Upload files，請注意一定要放在 .github/workflows 內，
   不要上傳到 GitHub 儲存庫根目錄。
5. 點 Actions → 我的基金雷達｜基金自動更新與發布，
   查看新的執行是否出現 build 與 deploy 兩個步驟並成功。
6. 成功後檢查 https://c87038-droid.github.io/fund-radar/

如果仍出現同樣的 No artifacts 錯誤：
請在 GitHub Actions 的新一次 run 進入 deploy Job，檢查 GitHub Pages deployment 詳細訊息。
那可能是 GitHub 的部署服務異常，單改 workflow 不保證可以排除。

此修正版只包含 GitHub Actions 發布流程，
不會更動 11 檔基金清單、淨值計算與頁面樣式。
